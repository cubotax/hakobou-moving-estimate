あなたはReplit上で動いている React+Vite + Express + LIFF 構成のデバッグ担当です。
「LIFFからLINEにメッセージが出ない」原因を切り分けるため、以下の“デバッグログ埋め込み”を実装してください。
目的は (1) LIFF側でfetchが実行されているか (2) サーバに /api/link が到達しているか を確実に確認することです。

# 1) サーバ側：/api/link に到達ログを入れる
- Expressのサーバファイルを探す（例: line-backend/server.js, server.js, index.js, app.js のいずれか）
- app.post('/api/link' ...) というルートを見つける
- そのハンドラの先頭に以下を追加する（asyncでも同様）:

  console.log('=== /api/link が呼ばれました ===');
  console.log('body:', req.body);
  console.log('ua:', req.headers['user-agent']);
  console.log('origin:', req.headers.origin);

- もし /api/link ルートが存在しない場合は新規で作成し、必ず 200 を返す（まずは到達確認用）:
  app.post('/api/link', express.json(), (req, res) => {
    console.log('=== /api/link が呼ばれました ===');
    console.log('body:', req.body);
    console.log('ua:', req.headers['user-agent']);
    console.log('origin:', req.headers.origin);
    res.status(200).send('ok');
  });

※ 既存の本処理（LINE送信処理）は一旦残してOKだが、最低でも到達ログが必ず出ること。
※ express.json() が全体で有効でない場合はこのルートにだけ付ける。

# 2) LIFF側：liff.html に「画面に出る」デバッグ表示を追加する
- liff.html を開く
- <body> 内の分かりやすい場所（上でも下でもOK）に以下を追加:
  <div id="debug" style="font-size:12px; white-space:pre-wrap; padding:10px;"></div>

- <script> 内の先頭に以下の関数を追加:
  function debug(msg, obj) {
    const el = document.getElementById('debug');
    const line = obj ? msg + ' ' + JSON.stringify(obj) : msg;
    el.textContent += line + "\n";
  }
  window.addEventListener('error', (e) => debug('window.error', { message: e.message }));
  window.addEventListener('unhandledrejection', (e) => debug('promise.reject', { reason: String(e.reason) }));

- 既存の main()（または初期化処理）を以下の“到達確認用”の流れに変更する:
  - debug('start') を最初に出す
  - await liff.init({ liffId: LIFF_ID }) を行い debug('liff.init ok') を出す
  - if (!liff.isLoggedIn()) { debug('not logged in -> liff.login'); liff.login(); return; }
  - debug('logged in') を出す
  - const profile = await liff.getProfile(); debug('profile ok', { userId: profile.userId })
  - debug('POST /api/link start') を出す
  - fetch('/api/link', { method:'POST', headers:{'Content-Type':'application/json'}, body: JSON.stringify({ lineUserId: profile.userId, test:'hello' }) })
  - const text = await res.text(); debug('POST /api/link done', { status: res.status, text })

- main() を必ず実行する（末尾で main();）

※ ここでは estimateId など本番データは使わず、まずは “/api/link が呼べるか” の切り分けだけをする。
※ fetch のURLが相対パスで失敗する場合は、サーバの公開URLを絶対パスで指定してもよい（例: https://<replit-app-url>/api/link）。

# 3) 動作確認
- Replitを Stop → Run で再起動
- LINEから「LIFFボタン」を押して liff.html を開く
- liff.html の画面に以下が出るか確認:
  start
  liff.init ok
  (未ログインなら) not logged in -> liff.login → その後自動で戻ってきて続行
  logged in
  profile ok { userId: ... }
  POST /api/link start
  POST /api/link done { status: 200, text: "ok" }

- Replit Console に以下が出るか確認:
  === /api/link が呼ばれました ===
  body: { lineUserId: "...", test: "hello" }

# 4) 成果物
- 変更したファイル名と差分（どこに何を入れたか）が分かるように提示する
- もし status が 404/500/failed の場合は、その原因（ルーティング/プロキシ/CORS/URL）を推定せずログ事実だけで報告し、追加で必要な修正案を提示する
