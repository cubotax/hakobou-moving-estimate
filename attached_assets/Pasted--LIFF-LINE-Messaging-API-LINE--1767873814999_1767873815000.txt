あなたはLIFF/LINE Messaging APIに強いフルスタックエンジニアです。
以下の症状を「確実に再発しない形」で修正してください。

# 症状
- 見積もり結果画面の「LINEで見積もり相談を始める」からLIFFが開くが、Flexメッセージが送信されない。
- サーバーログに /api/link が残らない（= LIFF側でPOST自体が発生していない）。
- 原因は、LIFFログイン後のリダイレクトで ?data=... が消えて、見積もりデータを復元できず処理が止まること。

# 要件（最優先：確実性）
- 「見積もり本文（長いdata）」をURLで持ち回らない。
- サーバ側に一時保存し、URLでは短いID（estimateId）だけを渡す方式にする。
- それでもLIFFの1次/2次リダイレクトでクエリが見えなくなることがあるので、
  LIFF側では URLの estimateId が無い場合でも liff.state から復元できるようにする。
  ※ LIFF起動時に liff.state に「LIFF URLに指定した追加情報」が入る仕様を利用する。

# 実装タスク
1) バックエンド(Express)
- POST /api/estimates を追加
  - body: estimate（見積もり入力一式。既存のフロントが持っている構造でOK）
  - 保存: まずは簡易で良いので in-memory Map に保存し、TTL（例: 30分）で削除する
    - key: estimateId（uuid推奨）
    - value: { estimate, createdAt }
- GET /api/estimates/:estimateId を追加（デバッグ用でもOK）
- POST /api/link を修正（または新規）
  - body: { lineUserId, estimateId }
  - estimateId から見積もりを取得し、Flexメッセージを作ってMessaging APIで送る
  - 送信失敗時はエラー内容をログに必ず出す（status code / response body）
  - 成功時も { ok: true } を返す

2) フロント（見積もり結果画面）
- これまで ?data=... でLIFFを開いていたのを廃止
- 見積もり結果確定時に POST /api/estimates して estimateId を受け取る
- ボタンリンクは以下のどちらかでOK（動く方を採用）：
  A) https://liff.line.me/{LIFF_ID}?estimateId=xxxx
  B) エンドポイントURL直叩きの場合は https://.../liff.html?estimateId=xxxx
  ※ どちらでもLIFF側で復元できるようにする

3) liff.html（最重要）
- 初期化後に以下を確実に実行する：
  - liff.init({ liffId }) を await（完了前にURL操作しない）
- estimateId の取得ロジックを実装：
  - まず通常クエリから取得: new URLSearchParams(location.search).get('estimateId')
  - 無ければ liff.state から復元（ここが肝）：
    - const state = new URLSearchParams(location.search).get('liff.state')
    - state があれば decodeURIComponent して、
      state が "?estimateId=..." 形式でも "/liff.html?estimateId=..." 形式でも解析できるようにする
    - 解析結果から estimateId を取り出す
- ログインフロー：
  - if (!liff.isLoggedIn()) { liff.login(); return; } とし、ログイン後に再実行される前提
  - ログイン後、liff.getProfile() で userId を取得（lineUserId）
- その上で POST /api/link { lineUserId, estimateId } を必ず実行
  - fetch失敗や estimateId 未取得の場合は画面にエラーメッセージ表示＋console.error
- 追加で「今どこで止まっているか」を確実に追えるよう、
  重要ポイントごとに console.log を入れる（init完了、estimateId取得、login判定、profile取得、api/link開始/成功/失敗）

4) 動作確認の手順も作る
- LINEアプリ内ブラウザで：未ログイン→ログイン→送信成功
- 既にログイン済みで：即送信成功
- 可能なら外部ブラウザで開いた場合の挙動もログに残す（liff.isInClient()など）

# 期待する成果物
- 変更後の server.js（または該当バックエンドファイル）の完全なコード差分
- 変更後のフロント（見積もり結果画面コンポーネント）のコード差分
- 変更後の liff.html（または同等JS）の完全なコード差分
- どのログが出れば成功/失敗が判断できるかのチェックリスト

# 重要
- 「dataをURLで保持する」「sessionStorage/localStorageに保存してログイン後読む」など、
  ブラウザ/セッション差で壊れやすい方法は採用しない。
- どうしてもURL経由で情報を持ちたい場合でも、長いdataではなく短いestimateIdのみ。
- Messaging API送信の失敗は必ずレスポンス詳細をログに出して原因特定できるようにする。
